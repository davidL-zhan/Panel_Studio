# 08 — Interaction Specification

> DDD 阶段 · 交互规范 · AI Panel Studio

## 1. 操作反馈

### 1.1 创建讨论
- 点击"创建讨论" → 按钮立即变 loading + disabled
- POST 成功 → 路由跳转到 `/discussions/:id`（此时 status=PENDING_PANEL）
- POST 422 → 对应字段标红 + 错误文案
- POST 500 → Toast "创建失败，请重试"，按钮恢复

### 1.2 生成嘉宾
- 进入 PENDING_PANEL 后自动触发生成
- 嘉宾区域显示 skeleton 网格（格数与选择的 expert_count 一致）
- 成功 → skeleton stagger fade-out → 嘉宾卡片 stagger fade-in
- 失败 → Toast "嘉宾生成失败：{原因}" + "重新生成"按钮

### 1.3 替换专家
- 点击某专家的"替换" → 该卡片 overlay 半透明遮罩 + 小型 spinner
- 成功 → 卡片内容交叉淡入淡出（200ms）到新专家
- 失败 → Toast 错误；卡片恢复原内容

### 1.4 全部重新生成
- 点击"全部重新生成" → ConfirmDialog："确定重新生成全部嘉宾？当前阵容将丢失。"
- 确认 → 所有卡片变 skeleton → 重新调用 LLM → 全新阵容 stagger 入场
- 取消 → 无变化

### 1.5 开始讨论
- 按钮可用条件：嘉宾阵容完整（已生成且每个 slot 非空），当前 status 为 PANEL_READY
- 点击 → 按钮变 "正在启动讨论引擎..." + loading
- 成功 → StudioView 渲染 + WS 连接建立
- 409 → Toast "当前状态不允许开始讨论"（可能已被其他 tab 启动）

### 1.6 结束讨论
- 按钮始终可见（IN_PROGRESS 态）
- 点击 → ConfirmDialog："确定结束当前讨论？主持人将进行总结。"
- 确认 → 按钮变 "正在生成总结..." + loading
- 成功 → 路由保留，视图切换为 EndedView + 展示总结
- 30s 超时 → Toast "总结生成超时，请稍后刷新查看"
- 已 ENDED → 幂等返回 200 + 已有总结（不会重复结束）

### 1.7 删除讨论
- 任意状态均可删除
- 点击"删除讨论" → ConfirmDialog："确定删除此讨论？所有数据不可恢复。"（确认按钮红色）
- 确认 → DELETE 请求，成功后路由跳转到首页
- 若 IN_PROGRESS → 后端会先强制停止引擎再删除，前端无感知

## 2. Transcript 滚动行为

| 场景 | 行为 |
|------|------|
| 新发言到达 + 用户在底部（距底 < 50px） | 自动滚动到最新 |
| 新发言到达 + 用户已上滚查看历史（距底 ≥ 50px） | 不滚动，右下角浮现 `ScrollToBottomButton` |
| 用户点击 ScrollToBottomButton | 平滑滚动到底部 + 恢复自动追随 |
| ENDED 态加载历史消息 | 分页按钮 "加载更多" 在上方，新加载的消息插入顶部（不跳滚） |

## 3. WebSocket 连接管理

### 3.1 连接生命周期
1. StudioView 挂载时建立 WS 连接
2. 收到 `initial_state` 后开始渲染
3. 用户离开 StudioView（路由切换 / 浏览器关闭）时断开 WS
4. DiscussionPage 卸载时断开 WS

### 3.2 断线处理
- 检测到断开 → TopBar WS 指示器切为黄色闪烁 + 文字"重连中..."
- Toast 通知："连接已断开，正在重连..."（仅首次断开时弹出）
- 客户端指数退避重连：1s → 2s → 4s（最多 3 次）
- 重连成功 → `?last_seq=N` 参数，服务端重放遗漏事件
- 重连成功 → TopBar 切为绿色 + Toast "连接已恢复"（2s 消失）
- 3 次失败 → TopBar 切为红色 + Toast "连接失败，请刷新页面" + 手动刷新按钮

### 3.3 事件去重
- 客户端维护 `lastSequenceId`
- 收到 `sequence_id ≤ lastSequenceId` 的事件 → 丢弃
- 收到非连续 sequence_id → 标记 missedEventCount → 下次心跳时上报

## 4. API 错误显示规范

| HTTP Status | 含义 | 用户可见 | 交互 |
|-------------|------|----------|------|
| 422 | 参数校验失败 | Toast + 字段级错误标记 | 修正输入后重试 |
| 404 | 资源不存在 | "讨论不存在" 页面 | 返回首页 |
| 409 | 状态冲突 | Toast "操作不允许：当前状态为 {status}" | 刷新页面 |
| 429 | LLM 频率限制 | Toast "服务繁忙，稍后自动重试..." | 自动退避重试 |
| 502 | LLM 错误 | Toast "嘉宾生成失败，请重试" | 手动重试按钮 |
| 503 | LLM 服务不可用 | Toast "服务暂不可用" | 手动重试按钮 |
| 500 | 服务器错误 | Toast "服务器内部错误" | 手动重试按钮 |

## 5. 重复操作防护

| 操作 | 防护策略 |
|------|----------|
| 创建讨论 | 按钮点击后 immediate disabled，直到请求完成 |
| 替换专家 | 单个卡片级 loading，不可同时替换同一位专家 |
| 开始讨论 | 乐观锁（后端原子性保障），按钮 disabled 直到响应 |
| 结束讨论 | 乐观锁 + 幂等（已 ENDED 返回 200） |
| 全部重新生成 | ConfirmDialog 二次确认 + 操作中按钮 disabled |
| 删除讨论 | ConfirmDialog（红色确认按钮）+ 操作中按钮 disabled |

## 6. 僵尸讨论检测

WS 心跳超时 30s 无任何事件 → 自动提示用户：
- TopBar 状态指示器切为红色 + 文字"引擎可能已停止"
- Toast："讨论引擎无响应，可能是服务异常。建议刷新页面或结束讨论。"
- 用户仍可点击"结束讨论"按钮（后端乐观锁处理实际状态）

## 7. Toast 堆叠策略

- 多条 Toast 堆叠显示（右上角向下排列），最多 3 条
- 每条独立计时（3s 后自动消失）
- 超过 3 条时最旧的立即移除
- 同类型消息（如重复的"重连中"）替换上一条而非新增

## 8. 实时讨论中的交互约束

| 约束 | 原因 |
|------|------|
| 讨论进行中不可修改嘉宾阵容 | SDD 状态机：IN_PROGRESS 只能转 ENDED |
| 讨论进行中可在首页看到（列表项可点击） | 加入观察（只读），新 tab 连接同一 WS 流 |
| 一个讨论可被多个 WS 客户端观看 | 所有客户端收到相同事件流 |
| 结束讨论后不可恢复 | 状态机不可逆，ENDED 是终态 |
